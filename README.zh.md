# dsh-behuman

[English](README.md) | 中文

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 加长期记忆和自进化技能的插件。

名字就是目标——让 dsh 像人一样了解你。

跟你共事一个月的人，会知道你在乎什么、喜欢怎么被告诉事情、哪些做法你已经否定过了，
也不会在同一个坑里摔第二次。

## 它解决什么问题

每次开新会话，AI 都从零开始。你告诉过它项目用的是 PostgreSQL，下次它又问一遍；
你纠正过它解释问题的方式，下次它还是老样子。

同一个坑反复踩。上次那个东西你折腾了三回才跑通，这次还得再折腾三回——
因为没有任何东西记得你当时是怎么绕过去的。

## 它做什么

- **记住你。** 你的偏好、你纠正过的事、你项目的状态，跨会话带着走。
- **自己变强。** 跑通过的做法会被写成技能，下次遇到同类任务，开局就已经会了。
- **不需要你操作。** 不用敲命令，不用管理记忆，装上就开始工作。

## 它是怎么工作的

装完之后有两件事在跑。

### 一、你聊天的时候，AI 顺手记

它本来就在对话里，所以看见什么值得留的，写个文件就行，不用额外叫模型。

它写东西的时机：

| 记记忆 | 写技能 |
|---|---|
| 你说了自己的偏好、习惯、项目里的约定 | 它干完一件麻烦事（5 次以上工具调用） |
| 你纠正了它，它按你的做法做成了 | 它修好了一个难缠的错误 |
| 它摸清了一条值得留的环境事实 | 它发现了一套能复用的流程 |

两列都守着一条前提：**得真的成了才写**。错误还挂着、按新做法还没跑通，都不写。
没解决的问题里总结出来的"方法"，下次照着做大概率也是白搭。

还有一条：**记成陈述句**。写「用户喜欢简短回答」，不写「要简短回答」——
后面这种在以后的会话里会被当成命令，可能反过来盖住你当时真正想要的。

### 二、它没记的时候，回头补

模型会忘，这个避免不了。所以**连着 10 次工具调用都没写过东西**（次数可配），
它会起一轮后台复审，把刚才那段对话重看一遍，看看漏了什么。

这是整个插件里唯一多花一次模型调用的地方，而且只在你没在干活的时候跑。

### 两边写出来的东西，走同一套检查

能不能写、是不是重复、文件叫什么名、目录要不要重建——一条不落。
后台那条没有特权。

### 整体流程

```
写入
  ├─ 顺手记：边聊边写
  └─ 补漏复审：没记的时候回头补
        │
        ▼  同一套检查
存储
  ├─ memories/     一条事实一个 .md 文件
  └─ skills/       一类任务一个 SKILL.md
        │
        ▼
取用
  └─ 目录常驻在提示词里，它看中哪一行，自己去翻那个文件
```

它不做检索。没有搜索这一步，也不会拿你的话去查库——目录本来就在上下文里，
翻不翻某个文件是它自己判断。所以"想起来"这件事不额外花时间。

但目录是要占地方的，而且会越占越多。每条记忆一行，每一轮都在 AI 眼前。
几十条的时候无所谓；到了几百条，就是实打实的钱了。这是这套设计已知的天花板——
要越过它，得从这些 Markdown 文件生成一个可搜索的索引，而不是拿数据库把它们换掉。

### 另外两点

- **同一件事说两遍 = 加强。** 新记忆跟已有的高度重合时，它会更新原来那条，而不是再加一条。
  一件事被反复提起，本身就是它重要的证据。
- **不会背着你藏东西。** 记忆就是普通的 Markdown 文件，你随时能打开、能读、能改、能删。

## 安装

`dsh` 每次跑的是一个 profile——一套命名好的插件搭配和配置，启动时由你指定。
自带的三个是 `web`、`tui`、`headless`。装进你平时启动用的那个：

```bash
dsh plugin --profile web add @goodddgrades/dsh-behuman     # 如果你用 dsh web 启动
dsh plugin --profile tui add @goodddgrades/dsh-behuman     # 如果你用 dsh tui 启动
```

装完就这样，不需要再开启什么。profile 是首次使用时自动创建的，所以哪怕你从没启动过也没关系。

同时用多个 profile 的话，每个都要装一遍。

### 或者，让你的 AI 去装

如果你已经在 dsh 会话里，上面那些命令一个字都不用敲：

> 帮我装一下 dsh-behuman 这个插件 —— https://github.com/goodddGrades/dsh-behuman

它能打开那个页面，自己把安装跑掉。

从 GitHub 直接装会在你机器上现场构建，所以 dsh 会停下来问你授权一次——它会告诉你具体加什么。
要构建的就是这个包自己的 `prepare` 脚本，你说可以之前它不会跑。

## 记忆存在哪

```
<你的工作目录>/.dsh/memory/
├── MEMORY.md          目录，每条记忆一行
└── memories/          记忆本体，一条一个 Markdown 文件
```

纯文本，你随时能看能改。每个项目目录有自己的记忆，换项目就换一套。

技能写在 `.agents/skills/`，跟手写的技能放在一起，用的也是 dsh 本来就能读的格式。

自动写的技能带标记。每个前面都有这两行：

```yaml
metadata:
  generated-by: dsh-behuman
```

所以你一眼就能看出哪些是 AI 写的、哪些是你自己写的。它只更新自己写的，绝不会动你手写的——
遇到手写的同名技能，它会拒绝而不是覆盖。

## 配置

每项都有默认值，想改才需要看这个表。

| 选项 | 默认 | 作用 |
|---|---|---|
| `dir` | `.dsh/memory` | 记忆存放位置 |
| `skillsDir` | `.agents/skills` | 技能写入位置 |
| `nudgeInterval` | `10` | 多少次工具调用没有写入之后，让它回头自查一遍。`0` 表示关掉 |
| `reviewBackend` | `spawn` | 自查用的子 agent，别动它 |
| `reviewTimeoutMs` | `60000` | 自查的超时时间 |
| `reviewMaxTokens` | `2048` | 自查的输出上限 |

## 状态

预发布。上面写的功能都是能用的——记忆能写、能跨会话召回、技能会自己写出来。
但它还没被作者以外的人跑过。
